# 任务 1-5：图像处理入门与条形码检测

## 已有基础与准备

你已经学习过 CNN、张量和图像数据。本任务新增的重点是传统图像处理：图像的像素与通道、灰度化、滤波、阈值分割，以及条码的定位和解码。现有 `dl-study` 环境已包含 OpenCV 5.0.0；无需重装 Anaconda 或 MATLAB。检测和解码的基础知识可参考 [OpenCV 官方条码教程](https://docs.opencv.org/5.0/tutorials/objdetect/barcode_detect_and_decode/barcode_detect_and_decode.html)。老师的视频为 [图像处理入门及 Python OpenCV 条形码检测](https://www.bilibili.com/video/BV1vkzjBKEV5/)；该页面未能在本次研究中读取，具体步骤以视频为准。

## 核心知识

1. 图像可看作数组：彩色图像通常为 `(高, 宽, 3)`，OpenCV 的通道顺序是 BGR；灰度图为 `(高, 宽)`。像素坐标的索引顺序是 `image[y, x]`。
2. `cv2.cvtColor(..., cv2.COLOR_BGR2GRAY)` 将彩色图像转换为单通道，便于后续处理。图像灰度化不会自动识别目标。
3. 高斯滤波对邻域加权平均，有助于抑制噪声，但太强会模糊条纹；Otsu 阈值根据灰度分布自动选阈值，生成黑白图。这里二值图用于观察，检测器接收的是模糊后的灰度图。
4. **定位**给出可能的条码区域，**解码**根据条空的编码规则恢复内容；定位成功不保证解码成功。本例使用 `BarcodeDetector.detect` 和 `detectAndDecodeWithType` 分别观察这两件事。OpenCV 官方教程列出的主要支持格式为 EAN-8、EAN-13、UPC-A 和 UPC-E，不要把该示例当作支持所有码制或二维码的通用识别器。
5. 官方案例介绍了基于局部梯度方向一致性的定位思路。平行条纹有相似的梯度方向；背景纹理、模糊和透视变化都可能造成失败。

## 运行

在 PowerShell 进入 `D:\computer_vision`：

```powershell
conda run --no-capture-output -n dl-study python .\任务1-5_OpenCV条形码\旧代码\barcode_demo.py
conda run --no-capture-output -n dl-study python .\任务1-5_OpenCV条形码\旧代码\barcode_demo.py --image '你的图片路径.jpg'
```

默认生成一张 EAN-13 合成图，结果写入 `旧代码/output/`：原图、灰度图、二值图、标框图和 JSON。2026-10-29 实测检测和解码成功，得到 `5901234123457`。这是合成样本，不能代表真实照片上的准确率。第一次直接处理合成原图时检测失败，改为 5×5 高斯滤波后成功；不意味着所有图片都应固定使用这个参数。

如果在 Notebook 中运行，先确认所选内核的解释器：`import sys; print(sys.executable)`。应指向 `D:\PythonWorkSpace\anaconda\envs\dl-study\python.exe`。如尚未注册内核，可运行 `conda run -n dl-study python -m ipykernel install --user --name dl-study --display-name "Python (dl-study)"`，然后在 Notebook 中选择该内核。

## 自己动手

- 打开原图、灰度图和二值图，比较形状、数据类型与像素取值；试试不同阈值和高斯核大小。
- 拍摄或准备一张清晰的 EAN 商品条码照片，运行第二条命令；记录是否定位、是否解码、识别内容与实际文字是否一致。对焦、光照、倾斜和条纹宽度都会影响结果。
- 修改照片角度或模糊程度，观察失败情形；区分没有定位与已定位但未解码。
- 报告建议记录：目的、环境、方法流程、输入图和结果图、真实输出、失败原因和改进。不要把合成图的结果写成真实照片测试。
